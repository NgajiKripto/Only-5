# Security and code-quality hardening pass

This change addresses findings from a prior code review, spanning private-key leakage, MCP input sanitization gaps, passphrase persistence, a race condition in strategy evaluation, URL protocol validation, magic-number extraction, versioned state persistence, error-swallowing, and conditional VACUUM. The approach is conservative: each fix is narrow, tests were confirmed passing without modification, and no behavioral changes were introduced beyond the security boundaries being tightened.

**Watch for:** The passphrase is now logged to stdout in plaintext (confirmed) — container log aggregation may capture it. The shell-injection regex has redundant `\n\r` and `\x0a\x0d` arms that match the same bytes (confirmed, cosmetic). The `evaluating` flag is a boolean guard, not a true mutex — it prevents overlapping async entries on the same event-loop tick but does not queue deferred evaluations (confirmed, by design but worth noting). No new tests were added for the new behaviors (URL protocol check, array sanitization, schema-version rejection, conditional VACUUM).

## High-level view

The private-key leak in `printBanner()` is eliminated cleanly — the banner now shows only "configured" or "not configured". The passphrase file-write is replaced with stdout logging, which removes the disk-persistence vector but shifts exposure to process stdout and any log collector attached to the container.

MCP input sanitization now covers arrays, newlines, redirects, and comments. The regex is broader than before, though it now blocks `#` and `>` which could appear in legitimate URLs — this is acceptable because the sanitizer operates on MCP tool parameters, not on user-facing URL fields. The `/scan` command separately validates URL protocol before it reaches MCP.

The evaluation mutex is a simple boolean flag with try/finally cleanup. It silently drops overlapping invocations rather than queuing them, and emits no log when a skip occurs — an observability gap under pathological conditions.

## Passphrase exposure vector shift

The old code wrote the passphrase to `data/auth-passphrase.txt` with mode 0600. The new code prints it directly to stdout:

```typescript
console.log(`[AUTH] ${authPassphrase}`);
```

This eliminates the on-disk persistence concern but shifts exposure to process stdout. In containerized deployments, stdout is typically captured by the container runtime's log driver (Docker json-file, journald, CloudWatch Logs). The passphrase now lives in log storage indefinitely unless log rotation or redaction is configured. The improvement is real — log access is generally more restricted than filesystem access on a running container — but it's a trade-off, not an elimination of the exposure surface.

## MCP sanitization: broader regex and array handling

The regex expanded from `/[;\`|]|&&|\$\(|\$\{/` to:

```
/[;`|><#\n\r]|&&|\|\||\$\(|\$\{|\x0a|\x0d/
```

The `\x0a` and `\x0d` hex escapes are redundant with `\n` and `\r` already in the character class — JavaScript treats them as the same bytes. No functional impact, just visual noise that could confuse a future maintainer into thinking they serve different purposes.

Array handling closes a real gap: previously, `typeof [] === "object"` meant arrays passed through to the generic object recursion path, which iterates `Object.entries()`. For an array `["a;b", "clean"]`, `Object.entries()` produces `[["0", "a;b"], ["1", "clean"]]` — so the old code would have caught string elements by accident. The new explicit `Array.isArray` check is still the right fix because it produces clearer error messages (reporting `param[0]` vs `param.0`) and handles nested objects within arrays correctly.

The existing test suite has no test case exercising array params or newline injection specifically — these new code paths are untested.

## Evaluation mutex: silent-drop observability gap

The `evaluating` flag prevents overlapping async evaluations and is cleared in a `finally` block. When a second call hits the guard, it returns immediately with no log or metric. Under pathological conditions (many slow strategies, network timeouts stacking up), the operator would see no indication that evaluations are being dropped. A `logger.debug("Skipping overlapping evaluation")` would cost nothing and aid debugging.

## URL protocol validation: redundant parse

The security command parses the URL twice — once in the try/catch for format validation, and again immediately after to inspect the protocol:

```typescript
try { new URL(target); } catch { ... }
const parsedUrl = new URL(target);
```

The second `new URL(target)` cannot throw (it already passed above), but it's an unnecessary allocation. Store the result of the first parse and reuse it.

## Schema-versioned risk state: first-deployment behavior

On the first deployment after this change, existing persisted state will have no `schemaVersion` field. `state.schemaVersion` evaluates to `undefined`, which is `!== 1`, triggering the warning log and a fresh start. This is the intended behavior and is harmless since risk state rebuilds from trading activity — but operators should expect the "schema version mismatch" warning on first boot after upgrade.
