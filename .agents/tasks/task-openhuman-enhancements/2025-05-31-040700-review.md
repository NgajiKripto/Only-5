# OpenHuman-inspired infrastructure expansion

Ten new modules spanning eventing, observability, data fetching, plugin loading, encryption, markdown export, a web dashboard, a Telegram command, feature barrel files, and integration tests. The approach is breadth-first: each module is self-contained with its own unit tests, connected via thin re-exports in `src/features/` and `src/core/index.ts`. The dashboard exposes internal agent state over an unauthenticated HTTP+WebSocket server. Encryption uses AES-256-GCM with PBKDF2 key derivation. Plugin loading executes arbitrary `.js` files from a directory path.

Watch for: Unauthenticated dashboard exposes metrics/strategies/memory to any network peer (confirmed). Plugin `loadFromDirectory` runs arbitrary code with no sandboxing or signature check (confirmed). WebSocket server implements only the happy-path upgrade; no ping/pong, no frame decoding, no close-frame handling (confirmed). PBKDF2 salt is generated but never persisted alongside the ciphertext (likely).

## High-level view

The dashboard binds an HTTP server on a configurable port with CORS `Access-Control-Allow-Origin: *` and no authentication. Any client on the network can hit `/api/status`, `/api/metrics`, `/api/strategies`, and `/api/memory/stats` to read agent internals. The WebSocket path is similarly open.

Plugin loading via `loadFromDirectory` performs a dynamic `import()` on every `.js` file in a given directory. There is no allowlist, no signature verification, and no permission boundary. A single malicious or corrupted file grants full process access.

The encryption API returns an `EncryptedData` object (ciphertext + IV + authTag) without the salt used for key derivation, creating a gap where callers must track salt separately or lose the ability to decrypt.

The WebSocket implementation handles the upgrade handshake and sends text frames, but does not decode incoming frames, respond to ping/pong, or send close frames. Long-lived connections will eventually be dropped by intermediaries expecting pong responses.

The auto-fetch manager uses `setInterval` without an initial fetch, so the first data arrives one full interval after `start()`. Fetch failures have no backoff or circuit-breaking.

The metrics collector's `completedSpans` array and `histogramValues` map grow without limit for the lifetime of the process.

## Dashboard: unauthenticated agent introspection

The `DashboardServer` creates an HTTP server with four JSON endpoints. The response headers include:

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
```

No token, cookie, or other credential is checked. The server listens on `0.0.0.0` (Node's default for `listen(port)`) unless the OS restricts it. Any host on the same network segment can poll `/api/strategies` to learn active trading strategies and `/api/memory/stats` to read memory contents.

The WebSocket upgrade path in `websocket.ts` is also unguarded — `handleUpgrade` checks only for the presence of `Sec-WebSocket-Key`, which every conforming client sends regardless of authorization.

The WebSocket implementation handles only the server-to-client broadcast case:

- Never reads incoming frames. If a client sends a ping, a text message, or a close frame, the raw bytes accumulate in the socket's read buffer until the OS tears it down.
- Never sends ping frames. RFC 6455 Section 5.5.2 requires responding to pings with pongs; many load balancers and proxies send pings to detect dead connections and will close sockets that don't respond.
- Never sends a close frame on shutdown. `DashboardServer.stop()` calls `server.close()`, which closes the HTTP listener but does not cleanly close WebSocket connections.

The `broadcast` method iterates `this.clients` and checks `client.destroyed`, but never removes destroyed sockets from the set during iteration. Sockets that error without triggering the `close` event will remain in the set indefinitely.

## Plugin loading: unconstrained dynamic import

`PluginRegistry.loadFromDirectory` reads all `.js` files from a user-supplied path and calls `import(fileUrl)` on each. The imported module's default export (or `.plugin` property) is trusted to conform to the `Plugin` interface and is immediately registered. When `initAll()` runs, the plugin gains full process access.

There is no:
- File signature or hash verification
- Allowlist of permitted plugin IDs
- Sandboxing (e.g., `vm` module or worker isolation)
- Permission model (the plugin has the same capabilities as the host process)

For a system that handles encryption keys and trading strategies, this is a significant trust boundary gap. A single file dropped into the plugin directory—whether by misconfiguration, supply-chain compromise, or path confusion—runs with full privileges.

## Encryption: incomplete envelope

`encrypt()` returns `{ciphertext, iv, authTag}`. `deriveKey()` takes a passphrase and salt, but the salt is generated separately via `generateSalt()`. Nothing in the API bundles salt with the encrypted output. A caller that loses track of which salt was used for a given ciphertext cannot decrypt. `rotateKey` does return `{...reEncrypted, newSalt}`, showing awareness of the problem, but the primary `encrypt` path doesn't. This will surface as a bug the first time someone serializes `EncryptedData` without separately persisting the salt.

## Auto-fetch: no backoff, delayed first fetch

`startSource` sets up a `setInterval` that fires after one full interval elapses. A source with a 60-second interval makes the system wait 60 seconds before the first data arrives. An immediate invocation of `fetchSource` in `startSource` would eliminate this startup latency.

On failure, `fetchSource` increments `failCount` and notifies the health callback, but the next retry fires at the same `intervalMs`. A source returning 429 or experiencing a network partition will be hammered at the configured rate indefinitely. The `OnHealthCallback` provides a hook for external circuit-breaking, but the manager itself has no backoff logic.

## Unbounded accumulation in observability

`MetricsCollector` stores every completed span in `this.completedSpans` and every histogram sample in `this.histogramValues`. Neither has a cap. In a long-running agent with frequent span creation (one span per fetch cycle), memory grows linearly with uptime. The `reset()` method must be called externally; there is no automatic eviction.

## Test coverage gaps

Not tested: the dashboard (server startup, request handling, WebSocket broadcast under real connections), plugin loading from a real directory, encryption round-trips through key rotation with salt management, and the auto-fetch manager's interval-based scheduling (the unit tests use manual invocation, not real timers). The `PluginRegistry` is exported from the Revenue feature module, which is architecturally inconsistent—plugin infrastructure is a platform concern, not a revenue concern.
