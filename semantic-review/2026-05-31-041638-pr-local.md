# OpenHuman-inspired infrastructure layer for Only-5 agent

This change adds ten new subsystems to the Only-5 autonomous agent: a typed event bus, observability/metrics collector, auto-fetch scheduler with exponential backoff, plugin registry with filesystem discovery, AES-256-GCM encryption service, memory-to-Markdown exporter, an HTTP/WebSocket dashboard, a Telegram `/dashboard` command, a feature-oriented re-export layer, and integration tests. Together they form the operational infrastructure for monitoring, extensibility, and data management. The approach is modular — each component is independently instantiated with no hard wiring between them — and each comes with its own unit test suite.

**Watch for:** Dashboard CORS is `Access-Control-Allow-Origin: *` with no authentication, exposing agent internals to any browser tab on the machine (confirmed). The AuditTrail has no size bound and will grow without limit in long-running processes (confirmed). The WebSocket implementation doesn't validate `Origin` headers or enforce any connection auth (confirmed). The plugin `loadFromDirectory` uses dynamic `import()` on any `.js` file it finds, which is a code-execution vector if the directory is writable (confirmed).

## High-level view

The event bus wraps Node's `EventEmitter` with a typed event map and a fixed-size circular history buffer. The wildcard subscription mechanism (`subscribeAll`) bypasses type narrowing — handlers receive `unknown` data.

The observability layer provides counters, gauges, histograms with percentile computation, and a span-tracing API. Both `completedSpans` and histogram sample arrays are bounded via constructor options with eviction. The histogram percentile calculation uses a sorted-copy approach that becomes O(n log n) on every read, though the 10k default cap makes this tolerable.

The auto-fetch manager uses `setTimeout`-chain scheduling with per-source exponential backoff (factor 2, cap 5x), immediate fetch on source start, and reset on success. The callback-based `onData`/`onHealth` pattern means only one consumer can be attached at a time — a second `setOnData()` call silently replaces the previous callback.

The plugin registry supports filesystem discovery via `loadFromDirectory`, which dynamically imports any `.js` file in the target directory. No sandboxing, signature verification, or dependency ordering between plugins.

The encryption module uses AES-256-GCM with random IVs and PBKDF2 (100k iterations, SHA-512). The main exposure is that no component manages key storage — the caller must handle passphrase/salt persistence, and the `EncryptedData` structure has no key ID or version field for multi-key scenarios.

The dashboard binds to `127.0.0.1` by default, but the HTTP API has no authentication and sets `Access-Control-Allow-Origin: *`. The WebSocket server implements RFC 6455 handshake and framing but does not validate the `Origin` header, read incoming frames (no ping/pong, no close frame handling), or limit connection count.

The test suite covers the happy path of each module with integration tests exercising memory consolidation and strategy execution end-to-end. Gaps exist around error paths, resource exhaustion, and the absence of auth testing.

## Dashboard security posture

The `DashboardServer` binds to `127.0.0.1`, which prevents remote network access. Local security is unaddressed in two dimensions.

`Access-Control-Allow-Origin: *` is set unconditionally on every response:

```typescript
res.setHeader("Access-Control-Allow-Origin", "*");
```

Any website loaded in the user's browser can make fetch requests to `http://localhost:3000/api/metrics` and read the response. For an agent managing financial strategies and wallet state, this is a data exfiltration path via any compromised or malicious tab.

The WebSocket upgrade path performs no authentication and no `Origin` header check:

```typescript
private handleUpgrade(req: IncomingMessage, socket: Socket, _head: Buffer): void {
  const key = req.headers["sec-websocket-key"];
  if (!key) { socket.destroy(); return; }
  // ... completes upgrade unconditionally
}
```

A malicious page can open `new WebSocket('ws://localhost:3000')` and receive the real-time broadcast stream. There is also no limit on the number of WebSocket connections, so a local process could open thousands of sockets without being throttled.

## WebSocket protocol gaps

The server implements only the write side of RFC 6455. It never reads from connected sockets — no frame parser exists:

- Browser clients send periodic ping frames. These are never answered with pong frames, so browsers will eventually time out the connection (typically 30-60 seconds of unanswered pings).
- Close frames sent by clients are never processed. The server relies on the TCP `close` event, leaving the protocol in an unclean state.
- Data sent by a client accumulates in the socket's read buffer indefinitely — a slow memory leak for long-lived connections with active clients.

## Plugin filesystem loading trust boundary

`PluginRegistry.loadFromDirectory` calls `import()` on every `.js` file in the given directory:

```typescript
const fileUrl = pathToFileURL(fullPath).href;
const mod = await import(fileUrl);
```

There is no sandboxing, no signature check, and no allowlist. If the directory path is configurable and an attacker can write to that directory, they achieve arbitrary code execution in the agent's process with access to all keys, wallets, and API tokens. The shape validation (`plugin.id` and `plugin.name` checks) does not establish provenance.

## AuditTrail unbounded accumulation

The `AuditTrail` class stores entries in a plain array with no maximum size:

```typescript
export class AuditTrail {
  private entries: AuditEntry[] = [];
  log(action: string, actor: string, metadata?: Record<string, unknown>): void {
    this.entries.push(entry);
  }
}
```

The `EventBus` uses a bounded `historySize` (default 100) and the `MetricsCollector` bounds both `completedSpans` (1000) and histogram samples (10000). The AuditTrail has no such bound. In a long-running agent that logs every encrypt/decrypt/rotate operation, this array grows indefinitely.

## Auto-fetch single-consumer callbacks

Calling `setOnData()` a second time silently replaces the previous handler. No error is thrown, no deprecation warning is logged. If two subsystems both need fetch data (e.g., metrics collector and strategy engine), one will silently stop receiving updates. The event bus exists in this same codebase and would be a natural fit for multi-consumer delivery.

## Encryption key lifecycle gap

The API surface leaves key/salt lifecycle entirely to the caller. There is no key ID embedded in the ciphertext, no versioning in the `EncryptedData` structure, and no keyring concept. If a system uses key rotation, it must track externally which salt belongs to which ciphertext. This becomes a foot-gun when multiple keys or multiple encrypted blobs are in play simultaneously — decryption fails silently with the wrong key (throws a GCM auth error) with no hint about which key version to use.

## Markdown exporter blocking I/O

`exportAll` calls `writeFileSync` in a loop over every memory entry. With hundreds or thousands of entries, this blocks the Node.js event loop for the entire duration of the export, stalling the agent's fetch timers, WebSocket broadcasts, and HTTP serving.

## Test coverage gaps

Not tested: dashboard authentication (because none exists), WebSocket connection limit behavior, plugin `loadFromDirectory` with malformed files beyond basic shape validation, auto-fetch behavior when `onData` callback throws, AuditTrail memory growth under sustained load, and the markdown exporter's behavior with filesystem errors (permissions, disk full).
